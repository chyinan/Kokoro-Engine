## 中文
### 概览
`v0.4.0` 是 Kokoro Engine 在 `v0.3.1` 之后的一次完整能力发布，不只是单个 provider 更新。本版本建立了角色生态与激活运行时、首次回复引导、静态内容 Registry、AstrBot 集成和 Codex Runtime，并同步强化了记忆、备份、内容安装、Webhook、CI 与多语言支持。

### 新增功能

#### 角色生态与运行时激活
- 新增角色目录、角色选择、角色推荐和角色详情流程，支持在主界面选择角色并恢复对应的交互状态。
- 新增角色激活运行时，将 persona、外观、语音、语言、动作 cue 和能力建议作为一个可回滚的激活操作处理；必需能力失败时不会留下半激活状态。
- 新增按角色隔离的实例、会话、记忆和资源路径，支持角色级运行时覆盖，不把 provider 凭据写入角色包。
- 增强 SillyTavern JSON/PNG 角色卡导入、角色合并和自定义头像/背景/Live2D 资源处理，并为内置角色和角色包补充 cue、许可证与资源说明。
- 新增角色包 manifest、兼容性声明、资源校验和创作者文档，并提供角色包模板。

#### 首次回复与记忆体验
- 新增可恢复的首次回复引导流程：从 provider 设置、角色选择到首条消息均可继续，并为取消、重复提交和 turn 关联增加保护。
- 将 provider 设置流程拆分为可测试的核心模块，改善 API key、OpenAI-compatible、Ollama 等路径的错误恢复。
- 记忆/embedding 模型初始化改为非阻塞；语义检索不可用时回退到可用的基础检索或普通聊天，不再阻塞首条回复。
- 增强会话、角色和记忆之间的关联，避免不同角色之间发生记忆 ID 碰撞或上下文串线。

#### 内容库与静态 Registry
- 新增 Registry v1 schema、静态索引和确定性构建器，内置 Kokoro、Pico、Seren 角色包及 `genshin-theme` MOD 包。
- 新增内容库 UI，支持浏览、查看兼容性与信任信息，以及角色/MOD 的安装、更新和移除流程。
- 为角色包与 MOD 包增加版本范围、大小限制、SHA-256、来源/信任标签、权限提示和回滚语义。
- 新增创作者角色包、MOD 包和 Registry 发布文档；第三方内容与官方内容继续使用不同的信任路径。

#### AstrBot 集成
- 新增独立的 AstrBot Kokoro 插件，通过 Kokoro 的带 Bearer 认证通用 Webhook 转发消息。
- 支持角色选择、私聊/群聊会话隔离、文本/图片/音频输入，以及文本、图片和 TTS 音频回复。
- AstrBot 继续负责平台和频道适配，Kokoro 继续负责角色、会话、LLM、TTS 与媒体处理；插件不读取或暴露 Kokoro provider 凭据，也不启动第二套服务。
- 新增插件配置 schema、安装/容器网络说明、curl 验证示例和针对 AstrBot `>=4.5.0` 的本地测试。

#### Codex Runtime（Experimental）
- 新增独立的 `Codex Runtime — Experimental` provider，通过本机 `codex app-server --listen stdio://` 复用用户现有的 Codex CLI runtime。
- Codex 继续负责认证、token refresh、`config.toml`、model provider、custom `base_url`、relay/proxy 和本地 provider；Kokoro 不读取或复制 `~/.codex/auth.json`，不导入 token，也不修改 Codex 配置。
- 新增 Codex executable 检测、app-server 生命周期管理、JSON-RPC/stdio 通信、thread/turn 流程、模型发现、流式输出、取消、重启和非敏感 transport 状态诊断。
- 使用临时、只读、无 execution environment 的 Codex thread，并关闭 Codex 自身的 shell、filesystem、MCP、Skill、Plugin、App、Connector 和搜索能力；Kokoro 的 Memory、RAG、MCP 和工具循环继续作为主控。
- 支持 Kokoro 工具的安全 dynamic-tool alias、工具调用续接和 canonical tool ID 恢复；按 JSON-RPC、turn acknowledgement、首输出、stream idle 和 total turn 分阶段处理 timeout。
- 设置页和所有六种界面语言均明确标注 `Experimental`；该 provider 不是 OpenAI Platform API，也不是 OpenAI 对 ChatGPT/Codex subscription 第三方 transport 的稳定契约承诺。

#### UI、配置与多语言
- 扩展 API、模型、备份、内容库、角色、MCP 和 onboarding 设置页面，补充状态、恢复路径、权限和兼容性提示。
- 完善简体中文、繁体中文、英文、日文、韩文和俄文的 provider、Codex Runtime、内容库和角色生态文案，并增加 locale key parity 检查。
- 更新 README、快速开始、架构、API、排障、角色包、MOD 包、AstrBot 和 Codex Runtime 文档。

### 修复与可靠性改进
- 修复角色卡人设在点击全局保存后重复追加 `Your name is ...`、用户称呼和用户姓名的问题；保存时保留用户原始 persona，运行时信息只在激活阶段组合。
- 为历史上已经污染的人设增加一次性、可识别片段清理，并在清理当前角色后刷新运行时。
- 修复 Codex dynamic tool 使用 `mcp__...` 保留命名空间时的请求错误、历史注入缺少 Responses item `type`/`input_text` 的错误，以及工具续接使用显示名而非 canonical ID 的错误。
- 强化备份创建、恢复、资源迁移和自动备份的路径边界、大小限制、临时文件晋级、重解析点/符号链接检查与失败回滚。
- 强化 Registry 下载、归档解压、manifest 校验、路径规范化、checksum、URL 重试状态和安装/更新/移除失败恢复，避免越界写入和不完整安装。
- 为 Webhook 和 AstrBot 请求增加 Bearer 认证、请求体限制、结构化错误、角色范围会话键以及文本/图片/音频媒体契约。
- 修复本地头像、背景和 Live2D 资源 URL 处理，以及角色描述长度、设置分组标签和界面状态同步问题。
- 改进 Sherpa/ONNX 构建缓存校验、Windows/Linux/macOS 构建工作流和 Node.js 支持版本矩阵；补充 issue、PR、角色包和 MOD 提交模板。

### 其他更新
- 保持现有 OpenAI Platform API、OpenAI-compatible、Anthropic、Ollama 和 llama.cpp provider 路径独立且继续可用。
- 将应用版本从 `0.3.1` 升级到 `0.4.0`，并同步更新 Tauri、npm、内置内容包和兼容性范围。
- 新增发布证据、反馈回收、创作者计划和外部集成发布流程文档；外部 Registry、AstrBot marketplace 和真实频道验收仍按文档单独记录，不以本地测试冒充外部发布证据。

### 兼容性说明
- `Codex Runtime — Experimental` 需要本机安装兼容版本的 Codex CLI；认证和 provider 设置必须先在 Codex runtime 中完成。当前开发环境以 `codex-cli 0.151.0` 验证。
- Codex app-server 属于实验性 runtime interface；方法、字段、事件、dynamic tool 命名规则和权限配置可能随 Codex 版本变化。遇到不兼容时 Kokoro 会报告错误，不会自动降级到更宽松的权限模式。
- 代理/VPN 环境下 Codex 可能先经历 WebSocket timeout/retry，再 fallback 到 HTTPS；Codex Runtime 已为此保留足够的首输出和总 turn 等待窗口，并区分 IPC、backend、stream idle 与 total turn timeout。
- Codex Runtime 不实现多账号轮换、额度绕过或 rate-limit evasion。
- AstrBot 插件当前目标为 AstrBot `>=4.5.0`，并需要一个可达且启用 Bearer 认证的 Kokoro Webhook；插件分发、marketplace 和真实频道兼容性需按外部验收记录。
- Registry 内置包声明与 `0.4.x` 引擎兼容；安装前仍会执行来源、版本、大小、checksum 和权限检查。
- 当前 Windows 开发环境的 Rust 单元测试执行仍可能受既有 `onnxruntime.dll` `STATUS_ENTRYPOINT_NOT_FOUND` 影响；测试二进制可以编译。

## English
### Overview
`v0.4.0` is a full capability release after `v0.3.1`, not only a provider update. It introduces the character ecosystem and activation runtime, first-reply onboarding, the static content registry, AstrBot integration, and Codex Runtime, while strengthening memory, backups, content installation, webhooks, CI, and localization.

### New Features

#### Character ecosystem and runtime activation
- Added the character catalog, selection, recommendations, and detail flow, allowing the main surface to select a character and restore its interaction state.
- Added an atomic, rollback-aware character activation runtime for persona, presentation, voice, language, cue, and capability settings; required failures no longer leave a partially activated character.
- Added per-character instance, conversation, memory, and resource isolation with character-level runtime overrides; provider credentials never enter character packages.
- Improved SillyTavern JSON/PNG card import, character merging, and custom avatar/background/Live2D resource handling, with cue, license, and asset documentation for bundled and authored packages.
- Added character-package manifests, compatibility declarations, resource validation, creator documentation, and a character-package template.

#### First-reply and memory experience
- Added resumable first-reply onboarding from provider setup and character selection through the first message, with guards for cancellation, duplicate submission, and turn correlation.
- Extracted provider setup into testable core modules and improved recovery for API key, OpenAI-compatible, and Ollama paths.
- Made memory/embedding initialization non-blocking; unavailable semantic retrieval falls back to usable basic retrieval or ordinary chat instead of blocking the first reply.
- Strengthened character, conversation, and memory association to prevent memory-ID collisions and context crossover between characters.

#### Content library and static registry
- Added the Registry v1 schema, static index, and deterministic builder, including the Kokoro, Pico, and Seren character packages and the `genshin-theme` MOD package.
- Added the content-library UI for browsing, compatibility/trust review, and character/MOD install, update, and removal flows.
- Added engine-version ranges, archive-size limits, SHA-256 checksums, source/trust labels, permission prompts, and rollback semantics for character and MOD packages.
- Added creator documentation for character packages, MOD packages, and Registry publication; official and third-party content retain separate trust paths.

#### AstrBot integration
- Added a separate AstrBot Kokoro plugin that forwards messages through Kokoro's authenticated generic Bearer-token webhook.
- Supports character selection, private/group conversation isolation, text/image/audio input, and text/image/TTS-audio replies.
- AstrBot remains responsible for platform and channel adaptation while Kokoro handles characters, conversations, LLM, TTS, and media; the plugin does not read or expose Kokoro provider credentials or start a second server.
- Added plugin configuration schema, installation/container-network guidance, curl examples, and local tests targeting AstrBot `>=4.5.0`.

#### Codex Runtime (Experimental)
- Added a separate `Codex Runtime — Experimental` provider backed by the locally installed `codex app-server --listen stdio://`.
- Codex continues to own authentication, token refresh, `config.toml`, model providers, custom `base_url`, relay/proxy, and local providers. Kokoro does not read or copy `~/.codex/auth.json`, import tokens, or modify Codex configuration.
- Added Codex executable detection, app-server lifecycle management, JSON-RPC/stdio transport, thread/turn lifecycle, model discovery, streaming output, cancellation, restart, and non-sensitive transport diagnostics.
- Uses an ephemeral, read-only Codex thread with no execution environments and disables Codex-owned shell, filesystem, MCP, Skill, Plugin, App, Connector, and search capabilities. Kokoro remains authoritative for Memory, RAG, MCP, and tool execution.
- Supports safe dynamic-tool aliases for Kokoro tools, tool-call continuation, and canonical tool-ID restoration; timeouts are separated for JSON-RPC, turn acknowledgement, first output, stream idle, and total turn duration.
- Settings and all six UI locales explicitly mark this provider as `Experimental`. It is not an OpenAI Platform API provider and is not a claim of a stable third-party transport commitment for ChatGPT/Codex subscriptions.

#### UI, configuration, and localization
- Expanded API, model, backup, content-library, character, MCP, and onboarding settings with status, recovery, permission, and compatibility guidance.
- Completed provider, Codex Runtime, content-library, and character-ecosystem copy for English, Simplified Chinese, Traditional Chinese, Japanese, Korean, and Russian, with locale-key parity checks.
- Updated the README, quick start, architecture, API, troubleshooting, character-package, MOD-package, AstrBot, and Codex Runtime documentation.

### Fixes and reliability improvements
- Fixed character persona text accumulating `Your name is ...`, user-address, and user-name instructions after every global save. Persisted cards now retain the user's raw persona, while runtime instructions are composed only during activation.
- Added one-time cleanup for recognizable generated fragments already present in persisted persona data and refreshes the active runtime after cleanup.
- Fixed Codex requests failing on reserved `mcp__...` dynamic-tool names, history injection missing the Responses item `type`/`input_text` fields, and tool continuation using display names instead of canonical IDs.
- Hardened backup creation, restore, resource migration, and automatic backup with containment, size limits, staged promotion, reparse-point/symlink checks, and failure rollback.
- Hardened Registry downloads, archive extraction, manifest validation, path normalization, checksums, URL retry state, and install/update/remove recovery against traversal and partial installs.
- Added Bearer authentication, body limits, structured errors, character-scoped conversation keys, and explicit text/image/audio contracts to Webhook and AstrBot requests.
- Fixed local avatar, background, and Live2D URL handling, character-description limits, settings-group labels, and UI state synchronization.
- Improved Sherpa/ONNX cache validation, Windows/Linux/macOS build workflows, and the supported Node.js matrix; added issue, PR, character-package, and MOD submission templates.

### Other Updates
- Preserved the existing OpenAI Platform API, OpenAI-compatible, Anthropic, Ollama, and llama.cpp provider paths as independent stable routes.
- Bumped the application from `0.3.1` to `0.4.0`, synchronizing Tauri, npm, bundled content packages, and compatibility ranges.
- Added release-evidence, feedback, creator-program, and external-integration publication procedures; external Registry, AstrBot marketplace, and real-channel acceptance remain separately recorded and are not inferred from local tests.

### Compatibility Notes
- `Codex Runtime — Experimental` requires a compatible Codex CLI installed locally, with authentication and provider setup completed by Codex. The development environment was verified with `codex-cli 0.151.0`.
- The Codex app-server is an experimental runtime interface. Methods, fields, events, dynamic-tool naming rules, and permission configuration may change between Codex versions. Kokoro reports incompatibility instead of silently falling back to a less restricted mode.
- In proxy/VPN environments, Codex may experience WebSocket timeout/retry before falling back to HTTPS. Codex Runtime preserves a sufficient first-output and total-turn window and distinguishes IPC, backend, stream-idle, and total-turn timeouts.
- Codex Runtime does not implement multi-account rotation, quota bypass, or rate-limit evasion.
- The AstrBot plugin targets AstrBot `>=4.5.0` and requires a reachable Kokoro Webhook with Bearer authentication enabled; plugin distribution, marketplace, and real-channel compatibility require separate external evidence.
- Bundled Registry packages declare compatibility with the `0.4.x` engine and still undergo source, version, size, checksum, and permission checks before installation.
- Rust unit-test execution on the current Windows development environment may still be blocked by the existing `onnxruntime.dll` `STATUS_ENTRYPOINT_NOT_FOUND`; test binaries compile successfully.
