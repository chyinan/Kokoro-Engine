## 中文

### 概览

`v0.4.5` 是 Kokoro Engine 在 `v0.4.0` 之后的一次稳定性与可维护性发布，重点收敛角色激活、聊天回合、会话切换、备份恢复、MOD 执行边界和本地构建缓存中的生命周期问题。本版本也同步更新应用版本元数据，并保留现有角色生态、内容 Registry、AstrBot 集成与 Codex Runtime 能力。

- **发布日期：** `2026-09-20`
- **上一版本：** `v0.4.0`
- **兼容性：** Kokoro Engine `v0.4.5`；现有 `0.4.x` 内容包兼容范围继续覆盖本版本。
- **隐私：** Kokoro 不收集自动远程分析数据；反馈、可用性和外部集成证据均为主动提供或人工记录。

### 新增功能与体验改进

#### 聊天与会话体验

- 持久化按角色隔离的输入草稿和输入区高度，统一可调整大小的输入卡片、草稿恢复和会话切换行为。
- 增加大图全屏预览、拖拽上传、图片草稿隔离和更稳定的消息编辑、重新生成、继续生成与会话侧栏交互。
- 恢复传统会话侧栏布局，并统一前后端的置顶、消息对齐和历史重写语义。

#### 角色激活与设置一致性

- 将角色激活并发门、取消处理、预变更屏障和补偿回滚贯穿完整聊天回合及 Bot 平台调用，减少切换过程中的半激活状态。
- 统一设置草稿、保存/取消、脏状态检查和运行时错误恢复；角色配置变更采用更清晰的原子边界。
- 增强启动恢复和单连接激活恢复，避免运行时表、会话状态和持久化配置出现不一致。

#### 备份、记忆与内容安全

- 修复按角色导入备份时的记忆映射，并强化并发恢复、资源迁移、临时文件晋级和失败回滚。
- 为 MOD 脚本增加执行边界和失败下载清理，减少脚本失控、临时文件泄漏和不完整资源残留。
- 继续保持 Registry、角色包和 MOD 包的来源、版本、大小、checksum、权限和路径校验；现有内置内容声明兼容 `0.4.x`。

#### 本地运行时与构建体验

- 修复 Codex Runtime 历史消息转换与会话历史恢复。
- 修复语音中断后的麦克风激活、过期 WAV 播放、聊天翻译事件类型和部分用户可见失败路径。
- 新增自动 target 缓存生命周期管理，强化 sentinel/link target 防护、磁盘水位处理、CI hook 初始化和测试隔离，并减少开发构建产物体积。
- 将默认启动窗口调整为 `1200×800`，并同步 API、架构、README、存储生命周期和多语言文档。

### 修复与可靠性改进

- 为聊天 turn 增加后端确认握手、请求身份绑定、取消传播、分阶段超时和锁恢复，覆盖丢失启动、提示词/钩子超时、工具审批取消、停止生成、重新生成以及回合失败后的清理。
- 防止会话切换期间发生跨会话草稿清理、图片校验串线、消息重复写入、工具行孤儿记录和错误的 assistant 消息对齐。
- 修复角色切换与聊天、宠物交互、Bot 调用之间的并发窗口；必需步骤失败时保留可恢复的激活和设置状态。
- 强化备份恢复的字符范围、记忆归属、并发提交和持久化错误处理，避免恢复后出现跨角色数据污染。
- 收紧 MOD 脚本运行和下载失败清理，继续执行路径 containment、符号链接/重解析点和临时目录检查。
- 改进本地存储缓存清理和旧分支兼容逻辑，避免链接目标、非 debug 产物和历史 hook 状态导致误删或缓存失控。

### 其他更新

- 应用版本从 `0.4.0` 升级到 `0.4.5`，并同步更新 npm、Cargo、Tauri、Nix 和 lock 文件元数据。
- 保留 OpenAI Platform API、OpenAI-compatible、Anthropic、Ollama、llama.cpp 与 Codex Runtime 的既有 provider 路径；本版本主要聚焦可靠性和生命周期修复。
- 补充并同步 API、架构、README、存储生命周期、CI 和外部集成相关文档；外部 Registry、AstrBot marketplace 和真实频道验收仍需单独记录。

### 兼容性说明

- 内置角色和 MOD 包使用 `>=0.3.1, <0.5.0` 的引擎兼容范围，覆盖 `v0.4.5`；安装前仍会执行来源、版本、大小、checksum、权限和路径检查。
- Codex Runtime 仍需要本机安装兼容版本的 Codex CLI，并继续遵循实验性 app-server 协议的兼容性限制。
- AstrBot 适配器仍要求 AstrBot `>=4.5.0`、可访问且启用 Bearer 认证的 Kokoro Webhook；本地模拟测试不等同于真实频道或 marketplace 验收。
- 当前 Windows 开发环境中的 Rust 测试执行可能继续受既有 `onnxruntime.dll` `STATUS_ENTRYPOINT_NOT_FOUND` 影响；若发生，仅记录环境阻塞，不弱化构建和测试门禁。

## English

### Overview

`v0.4.5` is a stability and maintainability release after `v0.4.0`. It focuses on lifecycle failures around character activation, chat turns, conversation switching, backup restore, MOD execution boundaries, and local build caches. It also synchronizes application version metadata while retaining the existing character ecosystem, content Registry, AstrBot integration, and Codex Runtime capabilities.

- **Release date:** `2026-09-20`
- **Previous release:** `v0.4.0`
- **Compatibility:** Kokoro Engine `v0.4.5`; existing `0.4.x` content compatibility ranges continue to cover this release.
- **Privacy:** Kokoro does not collect automatic remote analytics. Feedback, usability, and external-integration evidence is opt-in or manually recorded.

### New Features and Experience Improvements

#### Chat and conversation experience

- Persisted per-character input drafts and input height, with consistent resizable input cards, draft recovery, and conversation switching.
- Added large-image lightbox preview, drag-and-drop upload, character-scoped image drafts, and more reliable edit, regenerate, continue, and sidebar interactions.
- Restored the legacy conversation sidebar layout and aligned pinning, message alignment, and history-rewrite semantics between the frontend and backend.

#### Character activation and settings consistency

- Extended activation concurrency gates, cancellation, pre-mutation barriers, and compensation rollback across full chat turns and bot-platform calls to reduce half-activated states.
- Unified settings draft, save/cancel, dirty-state, and runtime-error recovery behavior with clearer atomic boundaries for character configuration changes.
- Improved startup recovery and single-connection activation recovery so runtime tables, conversations, and persisted settings stay consistent.

#### Backup, memory, and content safety

- Fixed per-character memory mapping during backup import and hardened concurrent restore, resource migration, staged promotion, and failure rollback.
- Added execution bounds for MOD scripts and cleanup for failed downloads, reducing runaway scripts, leaked temporary files, and incomplete resource residue.
- Preserved Registry, character-package, and MOD source, version, size, checksum, permission, and path validation; bundled content continues to declare `0.4.x` compatibility.

#### Local runtime and build experience

- Fixed Codex Runtime history-message conversion and conversation-history restoration.
- Fixed microphone activation after voice interruption, stale WAV playback, chat translation event typing, and several user-visible failure paths.
- Added automated target-cache lifecycle management, strengthened sentinel/link-target protection, disk-watermark handling, CI hook setup, and test isolation, while reducing development build footprint.
- Increased the default launch window to `1200×800` and synchronized API, architecture, README, storage-lifecycle, and multilingual documentation.

### Fixes and Reliability Improvements

- Added backend acknowledgement handshakes, request identity binding, cancellation propagation, staged timeouts, and lock recovery for chat turns, covering lost starts, prompt/hook timeouts, tool-approval cancellation, stop generation, regeneration, and failed-turn cleanup.
- Prevented cross-conversation draft cleanup, image-validation races, duplicate message writes, orphaned tool rows, and incorrect assistant-message alignment during conversation transitions.
- Hardened concurrency between character activation and chat, pet interaction, and bot calls; required-step failures now preserve recoverable activation and settings state.
- Strengthened backup restore character scoping, memory ownership, concurrent commits, and persistence error handling to prevent cross-character data contamination.
- Tightened MOD script execution and failed-download cleanup while retaining containment, symlink/reparse-point, and temporary-directory checks.
- Improved local storage-cache cleanup and legacy-branch compatibility to prevent linked targets, non-debug artifacts, and stale hook state from causing accidental deletion or cache growth.

### Other Updates

- Bumped the application from `0.4.0` to `0.4.5`, synchronizing npm, Cargo, Tauri, Nix, and lock-file metadata.
- Preserved the existing OpenAI Platform API, OpenAI-compatible, Anthropic, Ollama, llama.cpp, and Codex Runtime provider paths; this release primarily focuses on reliability and lifecycle fixes.
- Updated API, architecture, README, storage-lifecycle, CI, and external-integration documentation; external Registry, AstrBot marketplace, and real-channel acceptance remain separately recorded.

### Compatibility Notes

- Bundled characters and MODs use an engine range of `>=0.3.1, <0.5.0`, which covers `v0.4.5`; source, version, size, checksum, permission, and path checks still run before installation.
- Codex Runtime still requires a compatible Codex CLI installed locally and remains subject to the compatibility limits of the experimental app-server protocol.
- The AstrBot adapter still requires AstrBot `>=4.5.0` and a reachable Kokoro Webhook with Bearer authentication enabled; local mocked tests do not prove a real channel or marketplace acceptance.
- Rust test execution on the current Windows development environment may still be affected by the existing `onnxruntime.dll` `STATUS_ENTRYPOINT_NOT_FOUND`; if it occurs, record it as an environment blocker rather than weakening the build or test gate.
