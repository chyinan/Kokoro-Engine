# Rust MCP client migration

Baseline: `14473c46edfffe71f2ee3779ffc365d6a0308230`, before the SDK migration. The baseline column is from reading `src-tauri/src/mcp` and its callers at that commit; it is not a retrospective integration test.

| Contract | Baseline | SDK path |
| --- | --- | --- |
| Named server config | `mcp_servers.json` entries with name, type, command, args, env, URL and enabled state | Same serialized fields and defaults, both Streamable HTTP spellings, and URL-only `/sse` inference. No migration or third-party proxy is required. |
| Stdio | Own JSON-RPC framing, child and pending request map; Windows started `cmd /C` | SDK child process transport; direct executable or Windows `.cmd`/`.bat` shim, configured arguments and environment, drained stderr, owned child and process shutdown. |
| Streamable HTTP | Own POST and event parsing; session ID kept in app | SDK handles JSON and SSE responses, protocol metadata and session lifecycle. A lost session is surfaced to the app for explicit reconnection. No POST retry or redirect, and no SSE resume. |
| Legacy HTTP+SSE | Own long-lived GET, dynamic POST endpoint, IDs and pending requests | Compatibility transport retains only legacy GET and same-origin endpoint discovery/POST. It uses SDK messages and the 2024-11-05 initialize lifecycle. Discovery GET can follow same-origin redirects; a relative endpoint resolves against the final stream URL. It does not reconnect or fall back to a different transport. |
| Protocol and discovery | Proposed 2024-11-05; tools capability gated one page; list changes ignored | SDK negotiates 2026-07-28 discovery for stdio and Streamable HTTP, with initialize fallback for known older revisions. Unknown negotiated versions are rejected. Tool discovery walks a bounded cursor chain, publishes only completed lists and invalidates them on declared list-change notifications. The modern path subscribes when the peer declares support. |
| Invocation and results | Text joined into action output; image and embedded resource discarded by the action bridge; unknown block could reject the reply | Same action IDs, permission and approval policy. Standard text, image, audio, embedded resource, resource link and structured content are retained in action data; unknown blocks remain ordered JSON with a fallback label. The chat model receives the text summary and structured JSON, not inline media or fetched resources. Tool `isError`, JSON-RPC errors, timeout and transport failure remain distinct. |
| Connection ownership | Generation rejected stale completions; a lock around a tool call could delay shutdown | A disable, removal or replacement cancels the current generation, including a pending handshake. A stale action handle cannot dispatch against a replacement connection or catalog. A call that may already have run is never replayed automatically. |

The locked dependency is the official [`rmcp` 3.11.0 release](https://github.com/modelcontextprotocol/rust-sdk/releases/tag/rmcp-v3.11.0). It is enabled without default server or macro features. The app uses the released SDK's `client`, `transport-child-process`, `transport-streamable-http-client-reqwest` and `reqwest-native-tls` features. `reqwest` 0.13.2 was already locked via `sherpa-onnx`; the MCP path composes it directly to set redirect and retry policy. `tokio-util` supplies cancellation, `process-wrap` supplies child process ownership, and Windows uses `which` to resolve configured executables and shims. Native TLS follows the app's existing platform TLS dependencies. The published Rust minimums are 1.88 for rmcp and 1.87 for process-wrap; these do not raise the application's current Rust toolchain requirement.

[`rmcp` 0.10.0](https://docs.rs/crate/rmcp/0.10.0/features) exposes all three transports. [`0.11.0`](https://docs.rs/crate/rmcp/0.11.0/features) removed legacy client transport, and the [SDK's transport policy](https://github.com/modelcontextprotocol/rust-sdk#legacy-httpsse-transport-2024-11-05--intentionally-not-provided) confirms this is deliberate. The old all-in-one release predates current protocol negotiation and discards results it cannot deserialize as a known type; it does not expose the newer `CustomResult` fallback. The thin legacy binding keeps that one transport alive alongside a maintained client. See the [legacy transport spec](https://modelcontextprotocol.io/specification/2024-11-05/basic/transports) and [current transport spec](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports).

On Windows (Rust 1.99.1), all eight MCP tests passed in `cargo test --locked --manifest-path src-tauri/Cargo.toml`. The suite uses a real `.cmd` and Node subprocess, loopback HTTP, and an in-memory protocol fixture without external services or credentials. It covers scoped `PATH`, both Streamable HTTP eras, legacy SSE discovery redirects, pagination, notifications, capability and version checks, abandoned calls and deadlines, late generations, mixed and unknown content, and no replay after an HTTP error or redirect. The full suite also checks that direct action dispatch keeps its original handler and that raw SDK diagnostics do not enter the app log.

Real remote MCP services, TLS/proxy configurations, and native macOS/Linux processes need separate smoke testing. Configure the final URL for a Streamable HTTP endpoint that redirects, or for a legacy SSE discovery URL that redirects to a different origin. Stdio settings use a program and separate arguments; a server's configured `PATH` applies to its own lookup and child process. Child environment entries are never added to HTTP headers. Kokoro suppresses raw SDK log events because those can include session IDs and request URLs. Kokoro does not advertise roots, sampling or elicitation, and does not implement interactive or task result follow-ups.
