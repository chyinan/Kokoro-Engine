# v0.3.1 feedback and metrics review

This sample applies the Phase 7 review format to the existing public GitHub
Release for `v0.3.1`. It is a historical snapshot, not a claim that Kokoro
collected telemetry. Public asset counters can change after the observation
date, so the date and source are part of each value.

## Review gate

| Field | Value |
| --- | --- |
| Release | `v0.3.1` |
| Release URL | [Kokoro Engine v0.3.1](https://github.com/chyinan/Kokoro-Engine/releases/tag/v0.3.1) |
| Review window | Release publication through 2026-08-31 (observation snapshot) |
| Review owner | Kokoro Engine maintainer |
| Review date | 2026-08-31 |
| Decision before the next product phase | `Hold` |
| Next phase | Phase 7 follow-up release work |

`Hold` is appropriate for this sample because the public release counters are
available, but the human usability, registry, submission, repeat-participation,
and AstrBot evidence paths were not part of v0.3.1. A later release review
must be completed before its next product phase begins.

## Privacy boundary

Kokoro Engine does not collect automatic remote analytics. No application
telemetry, setup tracker, registry analytics endpoint, or AstrBot usage report
was used for this review. The only measured values below are public GitHub
Release asset counters observed through the public API.

## Feedback triage

The v0.3.1 release notes document QQ Bot, OpenAI Responses API, memory-decay
stability, and macOS packaging changes, but they do not provide a support,
usability, registry, or AstrBot adoption ledger. The release body is available
in the [public release page](https://github.com/chyinan/Kokoro-Engine/releases/tag/v0.3.1)
and the [repository release notes](../../release-notes/v0.3.1.md).

| Theme | Evidence | Impact | Owner | Next action | Status |
| --- | --- | --- | --- | --- | --- |
| Release asset demand is concentrated in the Windows installer counter | Public API snapshot above | Helps prioritize installer evidence, but does not measure successful setup | Maintainer | Capture per-platform usability evidence in the next review | Open |
| Human feedback evidence is absent | Metrics table above | Prevents a defensible completion or support-failure rate | Maintainer | Start the manual intake and five-session ledger for the next activation release | Open |

## Phase decision

### Blocking issues

- No clean-machine usability sessions for v0.3.1; owner: maintainer; evidence:
  [`first-reply-usability.md`](first-reply-usability.md); status: pending
  external acceptance.
- No registry or AstrBot adoption evidence for v0.3.1; owner: maintainer;
  evidence: [`registry-publication.md`](registry-publication.md) and
  [`astrbot-publication.md`](astrbot-publication.md); status: pending external
  acceptance.

### Decision rationale

`Hold`: 68 public installer asset downloads are recorded with a reproducible
source, but they cannot answer whether users completed setup or received a
first reply. The remaining required metrics are explicitly unavailable or not
applicable. The next product phase must establish the manual, opt-in review
workflow before treating any later release as evidence-driven.

### Corrections

If a public GitHub counter changes, append the observation date, old value, new
value, and reviewer here. Do not overwrite the 2026-08-31 snapshot.
