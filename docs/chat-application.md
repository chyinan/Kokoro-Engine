# 公共聊天应用服务

## 重构前的行为

| 入口 | 授权、输入与输出 | 上下文、工具和存储 |
| --- | --- | --- |
| 桌面、MOD、主动聊天 | IPC 绑定桌面角色与会话版本，支持流式文本、当前屏幕/相机、Live2D、主动 no-op、MOD hooks、TTS 播放和重连 | 已有独立任务与 journal。支持原生工具和文本标签、超时与取消。回复草稿和工具行写入 SQLite。最终保存错误曾仅记录日志，部分流错误曾被视作正常结束 |
| 通用 Webhook / AstrBot | Bearer、正文与媒体限制、角色/请求来源及私聊/群映射、图片和音频转写。返回文字、翻译、附件与音频 | webhook 根据角色和会话键构建稳定 ID，再用独立 orchestrator 装载历史。自有文本标签工具循环和记忆触发。流在输出一部分后报错仍可能返回部分回复，保存失败也可能返回成功 |
| Discord、LINE、QQ | 各平台认证、作用域、媒体下载或发送约束。LINE 图片转为桌面查看提示，QQ 支持文本，Discord 支持图片与语音 | 共用通用 Bot 循环。QQ 另有内存会话和排队，同一聊天在重启后可能丢失绑定。部分渠道读取桌面全局历史 |
| Telegram | 白名单与限流，文本、照片说明或语音转写，翻译、语音与图片回复 | 独立实现了文本和照片两个循环。读取桌面全局历史，`/new` 清理桌面选择，`/continue` 仅改变会话标记。空白名单实际放行，UI 与配置文档要求全部拒绝 |

权限判断、上下文归属、工具反馈、流失败和保存结果是分叉实现带来的差异。媒体格式、消息长度、平台会话身份、桌面 MOD hooks、实时显示及声音播放是入口或产品能力。

## 调用关系

```text
桌面 IPC ────────────────────────┐
主动聊天与桌面 MOD ───────────────┤
Webhook / Discord / LINE / QQ ──┼─ submit_chat → ChatRuntimeState → 应用任务
Telegram 文本 / 图片 / 转写 ───────┘                      │
                                                        ├─ 绑定角色和会话，写入用户消息
                                                        ├─ 共享 prompt 组装和 Provider 轮次
                                                        ├─ 共享工具执行器和技术行归属
                                                        ├─ 提交最终 SQLite 回复
                                                        └─ 记录结果，调度记忆与桌面附加任务
```

Bot、Telegram 文本和 Telegram 图片原有模型/工具循环、独立标签解释和记忆任务都已删除。应用层保留 `application.rs` 中的活动、绑定和持久化编排，把 Provider 流读取移到 `model_round.rs`，把记忆调度移到 `follow_up.rs`。原有 tags 测试覆盖工具和翻译，应用层继续使用跨轮清理，外部图片和控制标记测试位于共享 `tags.rs`。

- 桌面继承现有工作任务、会话版本检查、重生成、流事件、审批、视觉、MOD hooks 和语音播放。外部入口提交已授权角色、会话、消息 ID、文本或图片引用；Webhook 原始音频在公共任务接收后才转写，纳入忙碌拒绝、取消和准备超时。外部能力由 Rust 适配器设置，用户 JSON 不能开启桌面文件、屏幕、Live2D、通知、背景或交互审批能力。允许的工具仍受现有配置与执行器限制。
- Telegram 文本、命令、语音和照片统一先按当前完整配置快照检查真实 `chat_id`，再进入限流、会话或媒体处理。`allowed_chat_ids` 空或缺失时拒绝所有消息，Bot Token 不授予聊天访问权；群聊 ID 授权整个聊天，不是群内逐用户授权。保存后新增、移除或清空 ID 对后续消息生效，不强制撤销此前合法受理的任务。
- Telegram 默认按 chat 与角色隔离。`/new` 只轮换当前角色与该 chat 的私有绑定，首次发消息时才落库，保留其他角色与聊天的私有会话。`/continue` 显式固定调用时的桌面角色和会话，之后切换桌面选择不会重新指向其他会话。新会话与继续选择存于本次轮询服务中，重启后恢复到稳定默认绑定。
- 三类入口共用同一忙碌拒绝规则，包括同一会话的跨入口提交。目前也互斥不同会话的生成，沿用桌面历史编辑与角色切换的现有保护范围。被拒绝的同一请求 ID 会重放拒绝结果，有新输入意图时应发新消息 ID。
- 逻辑重复提交在进程内共享 journal 结果。Telegram、Discord、LINE 和 QQ 使用平台消息标识，Webhook 支持可选 `request_id`，实际身份按来源和聊天作用域构造。不同输入复用同一 ID 返回冲突。已提交的外部用户行绑定原角色与会话；重投先复用首次输入，再读取已提交回复或恢复进程内待保存批次。首次媒体准备失败、首次用户保存失败允许同 ID 再次尝试；已有用户行且没有可恢复回复时拒绝重新执行模型或工具。备份替换会使旧运行身份失效。
- 进程重启后也先检查平台请求的原角色归属，角色配置变化不能让同 ID 再次执行。旧版统一入口的 ID 与仅有 `source`/`client_request_id` 的记录同样参与检查；缺少可恢复保存身份时返回冲突。兼容 ID 只由 Rust 适配器按原平台和聊天身份计算，媒体下载或转录前使用同一检查。
- Webhook 音频指纹使用原始字节的 SHA-256 和格式，不使用可能变化的转写结果。相同输入重投会共享正在进行的任务或已提交结果，不再次调用 STT；不同音频、格式、文本或图片复用 ID 会冲突。首次转写失败尚未写入用户行时，修正服务配置后可使用同 ID 再试。仅工具输出的外部回合会保存可发送的完成提示，不暴露工具内部结果，也不重跑工具。
- 最终 SQLite 回复是完成边界。原生工具调用行、结果行与最终助手回复在同一事务提交，失败全部回滚。桌面“重试保存”和外部同 ID 重投只恢复原批次，不重跑模型或工具；恢复校验会话版本，缓存容量与生命周期见 `chat-persistence-boundary.md`。流读取失败仍不提供生成重试。隐藏桌面回合在最终事务才创建会话，审批和 Stop 在原 `None` 范围内可见；正常提交和保存重试均在选择锁内同步 journal 的会话 ID 与世代，取消或保存失败不留空会话。外部事件只进入 journal；桌面订阅按当前会话读取共享回合。
- 旧媒体兼容标记 `[IMAGE_PROMPT:…]` 进入共享工具循环，以前它可在 Bot 输出步骤直接调用生成器。现在受图片能力、工具配置、参数验证、取消和审批规则约束。结果包含图像附件或明确告警。TTS、媒体组装、平台发送和记忆失败各有独立反馈，已提交文字不因这些动作的失败被重新生成。
