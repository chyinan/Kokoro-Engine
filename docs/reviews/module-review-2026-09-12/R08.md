审查日期：2026-09-12。范围：启动 heartbeat、自动备份/记忆任务调度、主动聊天触发及 ChatPanel 消费、curiosity/initiative/idle、typing 延时和前端 reveal 生命周期。没有启动真实 provider 或读取凭据；生产代码未修改。

- 新增 [生命周期回归源码](evidence/R08-typing-listener-lifecycle.test.ts)、[执行记录](evidence/R08-typing-listener-lifecycle.json)、[原始日志](evidence/R08-typing-listener-lifecycle.log)。命令为 `rtk proxy npm test -- docs/reviews/module-review-2026-09-12/evidence/R08-typing-listener-lifecycle.test.ts`，结果 1 test failed；断言要求卸载后返回的 unlisten 被调用，实际为 0 次。

## 实际调度链

`lib.rs:803` 启动一次 heartbeat_loop。每轮 sleep 10 秒后读取 idle/conversation count，依次 curiosity decay、idle animation、await auto backup；每小时为捕获的角色 ID spawn prune；到设定时刻按当天条件 spawn Dream；最后按 5 分钟 idle、主动开关、10 分钟外层 cooldown 和 initiative 的概率决定发 proactive-trigger。

proactive-trigger 仅携带 trigger/idle/instruction，不携带角色或会话 ID。ChatPanel 消费时先检查 busy/TTS/audio，await memory readiness 后再次检查；此时从当前角色/会话 refs 形成 hidden streamChat 请求和 client_request_id。事件发出到消费之间的角色切换语义仍需单独测试，不能把已有 busy 检查忽略后宣称没有并发保护。

curiosity queue 最多 10 项、按 relevance 选择，heartbeat 每轮衰减；initiative 使用 Instant cooldown 与随机数；idle 行为有独立 cooldown。typing_sim 返回 200–5000ms 和 speed，当前 chat 调用输入 emotion/mood/expressiveness 是固定值。前端 useTypingReveal 使用 speed 调整字符 reveal，并在完成时由 ChatPanel 使用最终 cleanText 覆盖气泡文本。

## 发现

### R08-01 · P2 · 一个角色的每日 Dream 使其他角色当天不再被调度

代码位置：`src-tauri/src/ai/heartbeat.rs:50`、`:103`、`:110`、`:114`、`:126`、`:146`；`src-tauri/src/ai/memory.rs:1593`。

持久化查询 `has_dream_job_since` 按 character_id、trigger、started_at 去重；但 heartbeat 的 `last_dream_date` 是整个进程一个 Option<Date>。只要角色 A 当天已有任务或被触发，值就设为 today，之后即使切换到尚无 Dream job 的角色 B，也被外层日期判断直接跳过，甚至不会查询 B 的持久化状态。

触发条件：开启 daily Dream，A 达到 idle/时间条件后，同一天切到 B 并再次满足条件。影响：B 的每日整理被 A 抑制，行为与角色隔离的任务记录不一致。日期在后台任务运行前就提交，若尚未落 job row 就失败，当天也不会再次检查；已有失败 job 的重试策略需要明确决定，而非靠这个全局变量隐式实现。

验证状态：真实 gate 与数据库查询静态确认；没有运行时间推进或真实 Dream。修复建议：按 `(character_id, local_date)` 管理已检查/运行中/已完成状态，或以持久化角色状态为准；失败重试采用明确有界 backoff。不要让一次角色的成功/失败阻断别的角色。

### R08-02 · P2 · typing 监听器在注册完成前卸载后无法清理

代码位置：`src/ui/hooks/useTypingReveal.ts:69`、`:73`、`:75`、`:79`、`:83`、`:85`。

两个 effect 均在 listen().then 中赋值 unlisten，cleanup 仅执行 `unlisten?.()`。若组件在 listen Promise 解析前卸载，cleanup 时变量为空；Promise 随后解析只保存 handle，没有调用它。监听器保持注册并保留已经卸载 hook 的闭包。慢 IPC、快速切页或开发 StrictMode 均能产生这种时序。

影响：重复挂载/卸载累积全局 chat-typing/chat-cue 监听；它们虽只更新旧 refs，也持续占有注册与闭包资源。该问题不是单凭缺少测试推测；本地延迟注册回归已经失败，见上述原始日志。

修复建议：effect 维护 disposed 状态；Promise 返回后若已 disposed 立即调用 handle，否则保存供 cleanup。处理 listen rejection；两种订阅采用同一清理逻辑。修复后同一回归应通过，再覆盖正常挂载期事件和正常卸载各只清理一次。

## 必测场景与本轮结果

| 场景 | 静态结果 | 自动结果 / 未验证项 |
|---|---|---|
| heartbeat 重入与启动次数 | lib 启动一份串行 loop；prune/Dream 单独 spawn | 未做重复初始化/应用退出 task 清理测试；没有仅因 spawn 判定重复执行 |
| auto backup 慢操作与调度 | heartbeat await backup，期间其余本轮调度等待 | 备份域有基线；调度延迟、I/O 失败后下一轮未测，归 R17 联合验收 |
| prune 角色归属 | spawn 前捕获 char_id，调用带角色参数 | 未测角色切换期间 prune；没有发现调用结束时重新取 active ID |
| daily Dream 多角色、同日重入、失败 | 全局日期 gate 问题见 R08-01；DB 去重按角色 | 新时钟/barrier 场景未自动执行 |
| Dream 后台 provider/language 快照 | 捕获语言和角色；spawn 后取得 system provider | 角色与语言来自连续不同 await 的一致性未测；provider snapshot另见 R07 |
| 主动开关/idle/cooldown | heartbeat 检查开关/时间；消费端重验 busy/TTS/audio | 现有 ChatPanel 对 busy、audio、request ID、晚到 finish/cancel 测试通过 |
| proactive 等待中角色/会话切换 | 事件没有归属标识；消费时用当前 refs | 是否丢弃过期 trigger 需指定契约后测试；没有动态证明跨角色数据泄露 |
| curiosity 数据流 | add_topic 生产调用未找到，全仓调用只有 tests_autonomous.rs；当前 queue 常为空 | 不将未接线 queue 的跨角色或系统时间回拨风险报告为当前可达缺陷 |
| curiosity 测试发现性 | tests_autonomous.rs 有两个测试，但 ai/mod.rs/ai/tests.rs 没有引用该模块 | 基线实际 test list/log 没有 curiosity_queue_ordering/curiosity_decay；应接入后再宣称已覆盖 |
| initiative/idle 概率与时间边界 | 使用 Instant、随机数和固定 cooldown | 没有受控 clock/RNG 测试；未把随机概率本身定性为 bug |
| typing delay 数值与 speed | 输出 clamp 200–5000ms；当前聊天输入 persona 参数固定 | 5 个 Rust typing_sim 测试基线通过；实际个性化参数/预响应 duration契约待产品核对 |
| typing timer flush/reset/cancel | cleanup 会清 timer；ChatPanel 终态使用 final cleanText，取消 reset | 未把 correction 中 flush 的临时文本当持久化损坏；timer 重入/emoji/快速 active变化待测 |
| typing 异步订阅卸载 | delayed listen handle 没有释放 | 本次本地回归失败，R08-02 自动确认 |
| Windows 与其它平台 | 本次本地 React/jsdom 在 Windows 运行 | Tauri 真实窗口订阅生命周期未测；其它平台按 CI 独立验证 |
