# R12 图像生成

状态：服务与三个provider、IPC/UI配置入口静态审查已完成；新增受控provider回归等待统一Rust调度；真实付费生成未调用。

## 确认问题

### R12-001 / P1：取消生成后 busy 永久保留

imagegen/service.rs:146–161 compare_exchange置位后，只有 generate_inner.await 正常恢复才能清零。外部工具取消、超时丢弃future或task abort会跳过清零，下一次 generate 总返回generation already in progress。新增review_r12_cancelled_generation_must_allow_retry用真实service+本地pending provider，取消后断言下一请求能到达provider。修复使用drop安全的guard，并保留同一时刻只生成一次的语义。

### R12-002 / P2：provider响应未验证便保存为成功图片

service.rs:241–257直接按response.format构造文件名并写任意response.data；OpenAI/Google/SD成功JSON的base64字节没有统一图片校验。损坏或非图片字节会返回成功路径、界面显示坏图。新增review_r12_invalid_image_response_must_not_be_saved_as_success真实service回归。修复在统一落盘边界验证非空、大小、格式与图片可读性；失败不产生成功文件。

## 审查范围与场景

- provider选择：显式ID错误返回ProviderNotFound；默认缺失fallback与reload的顺序已检查。HashMap fallback顺序不是稳定产品策略，暂列维护建议。
- 请求参数：显式prompt与params.prompt、prefix/negative、auto尺寸分支已读；provider配置中size/quality/style是否应作为缺省值需与设置页契约联合核验，当前未给出完整动态结论。
- 输出：文件名UUID避免常规同秒覆盖；同步写失败返回GenerationFailed。磁盘满/权限失败真实故障注入未运行。
- 生命周期：取消busy见R12-001；providers读锁跨is_available/generate，reload会等网络完成，列待测响应性问题。
- 网络：每provider超时120秒并复用重试；成功/错误响应体当前缺少统一累计上限，服务落盘限额不能替代transport流读取限额。
- Google API key通过query拼入URL，utils/http.rs对reqwest错误直接格式化，网络错误可能把含key的URL写日志/展示。修复需采用头传凭据或在错误边界去URL，再用假key错误回归确认。

## 证据限制

新增回归仅使用临时目录与受控provider，不访问真实用户图片目录、不消费额度。已有Rust基线没有本模块专属service测试，因此874通过不能证明取消与响应验证正确。

生成 busy 状态现在由 Drop guard 释放；响应在写盘前必须是非空、限额内且可由 image crate 解码的图片。两项受控 provider 回归通过，真实 provider 的响应体限额和网络取消仍待 mock transport 补充。
