# R19 AstrBot 适配器

状态：已审完整 main.py、配置 schema、fake 与测试；8 个现有测试通过，真实 AstrBot runtime 和账号渠道未执行。

## 合约检查

- _component_payload → _webhook_payload → httpx POST → _reply_chain：文本、图片、音频开关；最多 8 张图片；30 秒请求超时；Bearer 头；非 2xx/无效返回处理。
- _media_format 固定 wav，匹配 Record.convert_to_base64() 之后的字节约定，未使用原文件扩展名误判。
- _image_mime_type 检查 component mime、data URL、扩展名与 mimetypes fallback。
- _event_identity 区分私聊/群聊及 platform_session；后端忽略 source/私聊显式 session 的缺陷在 R18-002 统一记录。
- 不把 fake AstrBot API 通过当作真实 SDK 版本兼容证明。

## 场景结果

8 个现有测试覆盖文本私聊、401 不泄露 token、连接失败、错误回复、私群媒体、platform origin、扩展名 MIME 和输出组件，见 evidence/astrbot-isolated-plugins.log。

默认 pytest 被本机额外 langsmith 插件及不匹配 pydantic-core 阻塞；在单个测试进程禁用插件自动加载、只加载 pytest_asyncio.plugin 后通过，未修改全局 Python 安装。

尚未执行 Python→真实本地 Rust HTTP→LLM→回复的贯通测试。修复 R18 后补 production parser 与 Python payload 对照；真实账号联调继续独立标记。

## 限制

媒体转换抛错与回复体积边界需补覆盖；当前外层 ValueError 提示 endpoint 无效，会混淆媒体转换的 ValueError，作为低影响诊断改进记录。现有 main.py 没有输出敏感 token 的日志。

适配器离线测试仍为 8 项通过；R18 后端认证、会话和媒体格式修复已由 Rust 回归覆盖。真实 AstrBot >=4.5 运行时、频道和 marketplace 发布证据仍待外部验收。
