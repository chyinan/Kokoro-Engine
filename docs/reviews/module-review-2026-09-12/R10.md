# R10 STT、麦克风与唤醒

状态：已完成静态审查和本地生命周期回归，生产修复正在进行；本机麦克风、唤醒词和本地模型未实测。

## 调用链

`useVoiceInput`/`useWakeWord` 选择 browser 或 Tauri native 采集；`stt/mic.rs`、`stt/wake_word.rs`、`stt/stream.rs` 处理 PCM 缓冲、snapshot/complete/discard 和识别事件；`stt/service.rs` 路由 OpenAI-compatible、whisper.cpp、SenseVoice；结果进入 ChatPanel 并绑定回合代次。

## 已确认问题

- **R10-001/P1：唤醒词停止/卸载期间迟到授权仍启动采集。** `useWakeWord` 原先没有 capture generation；延迟 `getUserMedia` 返回后继续创建 AudioContext/processor。新增回归已复现，已增加 generation 与 track/context 清理。
- **R10-002/P2：native 麦克风停止没有等待后台帧消费任务。** `mic.rs` 停止路径释放 stream，但转录/事件消费可能在之后追加到旧 AudioBuffer 并发出迟到唤醒或识别结果。需要 join/cancel owner 和回合代次检查；本轮静态确认，未做硬件复现。

## 既有覆盖与缺口

Rust 基线包含 stream、provider 与配置相关测试，Vision stress 5 项通过；没有真实设备测试目录覆盖 `mic`、`wake_word`、`sensevoice_local` 的完整生命周期。应使用固定 PCM/WAV、假设备、临时模型目录覆盖 NaN/Inf、120 秒上限、设备拔出、下载中断和关闭后的迟到结果。

## 环境边界

拒绝麦克风权限、设备切换、本地模型推理和唤醒词准确率必须在隔离 Windows 桌面环境记录；mock 通过不代表真实设备通过。关闭采集后，任何迟到结果均不得写入新角色/会话。
