## 确认问题

### R21-001：完成 IPC 回包丢失 finish 事件时桌宠保持永久 streaming（P1）

- 位置：`D:/Programs/Kokoro-Engine/src/features/pet/usePetChat.ts:144-219`，尤其 `:196-203`。
- 触发：`stream_chat` 返回 `{ status: "completed" }`，但没有收到 `chat-turn-finish`。
- 预期：根据权威 IPC 回包清理 streaming、当前 request/turn 和 bubble 生命周期，下一条消息可以发送。
- 实际：`sendMessage` 等待 `invoke` 后直接结束；`setIsStreaming(false)` 只在 finish/error/reject 监听中执行，当前测试观察到 `isStreaming === true`。
- 影响：桌宠会一直认为自己忙碌，后续消息被第 146 行的本地门禁拒绝；bubble 也不能按完成回包进入正常隐藏流程。
- 修复建议：复用状态收敛函数，在 `stream_chat` 返回值为 completed/error/cancelled 时按当前 request ID 清理；迟到事件仍必须经过现有归属校验，不能清理下一轮请求。补充 completed、cancelled、error 三种回包和 finish 同时到达的幂等回归。
- 复核状态：未修复，未独立复核。
