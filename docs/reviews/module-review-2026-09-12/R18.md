## 确认问题

### R18-001 / P1：未配置 Bearer 时认证放行

commands/bot.rs:2110–2112 的 verify_webhook_bearer 在 expected token 缺失/空白时返回 Ok，start_http:462–486 也不拒绝缺失 token。与仓库 authenticated webhook 约定不符；启用或恢复空凭据配置后，接口接受未认证请求。新增 review_r18_webhook_without_configured_token_must_reject_requests 调用生产校验函数；修复应在启动和请求入口均拒绝缺失凭据。

### R18-002 / P1：不同平台或显式私聊会话映射为同一历史

webhook_conversation_key:2129–2162 私聊先取 user_id，source 仅作缺少 ID 时的 fallback。来自不同平台的相同用户 ID，或 AstrBot platform_session 中同一用户的不同 unified_msg_origin，得到同一 key。prepare_webhook_conversation:2271–2295 根据该 key 的 hash 加载历史，造成会话合并。新增两个 review_r18_* 测试调用生产 key 函数；修复需让 source 和显式 conversation_id 参与无歧义身份，并记录旧历史兼容策略。

### R18-003 / P2：HTTP filter 拒绝响应不遵守 JSON 错误契约

run_http_bot_server:2007–2034 使用 content_length_limit 后直接 serve，没有 recover。超过路由上限/缺少所需长度等请求在 handle_generic_webhook 前被 Warp 拒绝，返回框架默认文本，而 parser 测试只覆盖进入 handler 后的错误。修复应在实际 route 接 recover，并补 route 级 JSON/状态码测试。

### R18-004 / P2：语音回复固定标记 OGG，与 provider 字节不一致

attach_voice_reply_to_webhook:1937–1946 及 Discord 发送路径把 synthesize_text 的原始 Vec<u8> 标记为 audio/ogg/reply.ogg。tts/openai.rs:131、187 明确请求 mp3，TtsProvider 契约也允许 MP3/WAV/PCM，manager:510–540 没有转码。应由音频实际格式产生 MIME/扩展名，未知格式明确降级；不能只改入站 AstrBot WAV。
