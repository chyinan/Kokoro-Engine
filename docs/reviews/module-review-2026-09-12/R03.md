## 确认问题 R03-001：激活失败恢复到过期的会话选择（P2）

- 位置：`activation.rs:246–248` 以持久化 committed runtime 构造 `previous_committed`，`:431–449` apply 失败后把该快照交给 restore；`commands/conversation.rs:165–173` 加载会话只更新 live selection 和选择文件，不更新 committed runtime 表。
- 触发：激活角色 A（会话 X）→通过历史侧栏切到 A 的 Y→尝试激活 B→注入 backend.apply 失败。
- 预期：失败后继续使用角色 A / 会话 Y / Y 的历史。
- 静态确定的实际行为：restore 恢复 A 的旧 X。前端异常处理又调用 get_committed_character_runtime，仍会将 X 的 target_conversation_id 分发回聊天窗口。用户失去当前会话位置，后续上下文被退回 X；已有会话内容不会因此从数据库删除。
- 新增复现：`src-tauri/src/characters/activation_tests.rs` 的 `failed_activation_preserves_conversation_selected_since_previous_activation`。实际执行 coordinator.prepare/commit，以现有 TestBackend 注入 apply 失败，断言 live conversation 和 history 仍属于 Y。**尚未执行 Rust**，需要总审保留红测输出后独立确认；目前缺陷证据是确定的生产调用链。
- 修复建议：在激活门禁内捕获当前有效的会话选择供补偿使用；保留 committed 快照对角色配置及资源的权威性；同步考虑前端 catch 通过 recovery 再次覆盖选择的问题，不能只改一次 backend.restore。新增回归同时覆盖前端失败恢复后的会话选择。
- 复核状态：已交总审；未修复、未独立复核。
