## 1. 方法与范围

主代理先完整阅读五份文档、核对仓库状态，再由三个独立子 Agent 分别审查源码与图形链路、架构与算法、模型与原生运行时。第一轮独立提出反例和来源，主代理裁决后分文件修订；第二轮交换审查对象，源码组复查 03/04、架构组交叉核对五篇、模型组复查 03 契约。主代理逐项处理异议并做最终一致性与文档检查。

使用本地 `kokoro-contract-review-and-pr` 技能指导源码/载荷/消费者追踪及发布验证；通过 Context7 MCP 查询 ONNX Runtime 的 RunOptions，再使用官方 runtime 文档、模型发布者卡片、锁定图形依赖源码及原论文核实具体主张。模型卡只证明发布者描述，不替代固定产物或本机实验。各篇就近附来源。

文档中的“请实施”“签署通过”是被审查内容，不是本次执行指令。本次只修改研究文档，不实施情感引擎，不下载模型，不收集或上传聊天语料。用户已有 `.gitignore` 修改及本目录之外的研究文件不属于此次提交。

采纳的价值诉求是及时倾听、角色回应与资产适配；反方限制是证据不足时弃权、现有行为可回滚、原生任务与文件操作不作绝对保证。最终不是把两方提案简单叠加，而是减少重复所有者和未经验证的功能承诺。

## 3. 第二轮：审查修订稿本身

| ID | 修订后仍存在的反例 | 最终处理 |
| --- | --- | --- |
| R2-01 | 一个窗口重建推进全局激活代次，另窗口错误丢弃 | activation_epoch 只由激活 owner 推进；viewer_epoch/adapter_generation 窗口本地，L2 generation 独立 |
| R2-02 | L1 在 ack 前 turn=null，ack 后无绑定规则 | 唯一 request→turn/conversation 映射；仅有效原请求可归一化，旧请求不得冒用当前回合 |
| R2-03 | unavailable 广播无身份，旧超时清掉新结果 | 返回值由调用闭包关联；广播必须外加完整身份/代次/序号 |
| R2-04 | 50ms 又从后端接纳或排队重新计满 | 从提交起算端到端接受预算，后端仅扣剩余预算，跨进程不比较绝对单调时钟 |
| R2-05 | 当前音频回调只有 boolean，句级近似也无依据 | 未有真实片段关联时仅回合级；G4 要求结构化播放事件及拒播/失败/耗尽终态 |
| R2-06 | chat-turn-finish 先于 TTS 完成，目标被提前撤销 | 生成终态与播放终态分开；已排队目标延续到对应播放终态或 TTL，取消即时撤销 |
| R2-07 | MOD/手动 cue 迁移遗漏或变成最高优先级 | 列出全部旧生产者；非聊天来源独立路由，不伪造身份，不静默声称兼容 |
| R2-08 | 04 推理 adapter 与渲染 ModelAdapter 同名 | 推理后处理改名 InferenceOutputAdapter；图中顺序统一为能力映射→UPB→提交 |
| R2-09 | 输入上限、性能预算、平滑算法各篇仍有不同默认值 | 03 单一基线；2048 bytes→NFC 512 scalars→L2 ≤64 tokens，一阶滤波、L1 P95 ≤5ms 初始预算 |
| R2-10 | D 缺失仍参与全矩阵；有限巨大权重仍溢出 | 禁用缺失 D 行列，仅 VA 子矩阵；q≤1、项数≤1024、重复贡献封顶 |
| R2-11 | 重叠区间选择不确定，诊断字段不在 schema | 固定左端点/最长/优先级/ID 次序；内部诊断不冒充新增 wire 字段 |

这些条目均已落实到 01–05。最终闭环回查中，源码组确认播放身份、生成/播放终态、旧 cue 兼容三条阻塞关闭；架构组确认所有者、数学、预算与代次问题关闭，未发现剩余严重矛盾。最终权威契约见 [03](03-facial-expression-technical-selection-and-architecture-design.md)。审查范围内没有保留未裁决的文档冲突；实现方案是否达到门槛仍需实际代码与实验。
