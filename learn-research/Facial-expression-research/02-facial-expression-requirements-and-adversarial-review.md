# 面部表情系统：需求基线与对抗性审查裁决

> 状态：设计建议，尚未实现或完成体验验收。当前实现证据见 [01](01-current-emotion-to-expression-pipeline-analysis.md)；最终边界与契约以 [03](03-facial-expression-technical-selection-and-architecture-design.md) 为准。原文模拟角色辩论不作为真实测试、专家签署或发布批准的证据。

## 1. 需求与范围

目标是让角色在收到自然语言后给出及时、适度的倾听反馈，并在回答时呈现与角色表达一致的面部变化。这里的“精准”必须通过有标注的评测来判断，“自然”必须通过真实模型上的视觉验收来判断，不能保证所有语言和所有模型都完美识别与呈现。

本阶段只接管声明支持的眉、眼睛开合、脸颊和嘴部通道，眼球注视与瞳孔保持 SDK 既有行为，不增加歪头、身体位移、全身 motion 或骨骼动作。原有全身功能的兼容与面部新功能分别验证。

用户情绪、助手话语情绪、角色反应是不同对象。例如用户说“我今天很难过”，感知结果可能是负向情绪，角色适宜给出关切，而非机械复制悲伤强度；用户引用“他说自己很开心”，也不能直接解释为用户本人喜悦。

## 2. 模块边界如何满足需求

| 模块 | 唯一职责 | 不应承担的职责 |
| --- | --- | --- |
| L1 感知 | 有界文本输入到 `PerceptionEvidence`，支持未知和弃权 | 人格变换、会话惯性、帧时间、FACS 与模型参数 |
| 可选 L2 感知 | 在预算和有效期内提供同结构的修正证据 | 阻塞 L1、主对话或渲染；直接改表情 |
| ResponsePolicy | 将来源明确的证据和角色配置转成角色反应意图 | 操纵 Cubism 或保存帧级动画状态 |
| FaceState | 仲裁意图、优先级、生命周期与有效性 | 再做文本分类或重复人格变换 |
| ModelAdapter | 探测资产能力、校准语义与参数映射 | 把参数名字推测当成可靠的表情含义 |
| UPB | 在明确的帧内提交位置混合已接管面部通道 | 调用文本模型、等待 IPC 或重复管理回合生命周期 |

L1 立即产生可用证据或明确弃权结果；L2 在后台尝试修正。即使 L2 永不完成、模型不可用或返回无效结果，主对话和中性倾听仍可使用。

## 3. 多轮对抗性审查的需求裁决

### 3.1 即时反馈与误判

**反例**：“我一点也不开心”“谢谢你把我的文件删了”“虽然中了大奖，但发现彩票过期了”。简单关键词触发会给出错误的正向反馈；增加神经模型也不自动消除反讽与归属歧义。

**裁决**：即时反馈首先允许低幅度中性专注；可用证据再决定偏置。输出须区分来源、置信信息与弃权，不能把置信分数直接当成表情强度。无标注依据时不承诺固定准确率。词典、规则和模型的收益必须相对同一基线、同一测试划分验证。

### 3.2 流式表情与实际语音

**反例**：文本生成很快，但 TTS 排队缓慢；若每收到 token 就更新表情，角色仍在读上一句却已切换到下一句情绪。即使使用分句边界，生成时间也不是播放时间。

**裁决**：有语音时以实际播放状态与片段身份对齐表情；纯文本模式另用文本呈现节奏。保留现有 `play_cue` 兼容。新 `[emo:...]` 协议只有在增量解析、最大缓冲、畸形标签、分块截断、取消、重试、去重以及正文/TTS 不泄漏验证通过后才能启用。不能立即删除当前后置兜底并假定所有模型都遵守新协议。

### 3.3 模型适配与安全降级

**反例**：模型使用标准参数名却反向绑定，或者只有 `F01` 等无语义文件名；即使参数在 `[min,max]` 内，也可能出现错误或不适宜的神态。

**裁决**：显式角色/模型配置优先，名称启发只生成待校准候选。已有 expression 可作为资产方案，但其 add/multiply/overwrite、fade 和参数占用必须纳入适配。缺少可信映射时跳过该通道，最低降级是保持既有中性表现，而不是强制合成喜怒哀乐。参数范围必须读模型真实声明，不以标准命名表中的常见范围替代。特殊图层效果要核查其实际绑定，不假定所有 `.exp3.json` 都直接控制 Part 透明度。

### 3.4 嘴型与统一写入

**反例**：在外层 ticker 相加 `baseline + lipSync`，后续 expression 或 physics 又覆盖结果；或者把同一个表达式偏置计算两次。单纯 clamp 不能解决写入所有权问题。

**裁决**：先确认依赖版本的帧顺序，再定义已接管通道的基值来源与唯一最终提交位置。UPB 不额外复算已由 expression 应用的偏置。口型开合、嘴角发音偏移、情绪基底分别有输入和约束；具体增益必须通过资产校准。未接管通道继续遵循原运行时行为。

### 3.5 多窗口、取消与状态泄漏

**反例**：角色 A 的慢推理在切换到角色 B 后返回；旧回合 TTS 播放回调迟到；模型重新加载后仍使用旧参数索引；广播事件被多个 Viewer 无差别消费。

**裁决**：新事件必须具有可核验的角色、会话、回合与模型/激活代次身份以及顺序和有效期。FaceState 在取消、切换、停止、销毁和超时中统一失效化状态。异步资源加载完成后也要重新验证代次，不能只在开始加载时检查。旧 `chat-cue` 没有这些身份，必须独立定义兼容边界，不为它编造新身份后混入新链路。

## 4. 交互阶段与验收方式

| 阶段 | 期望行为 | 验收观测 |
| --- | --- | --- |
| 输入被接受 | 主对话立即开始；基础感知独立运行 | 记录输入接受、基础结果、首个可见反馈，证明不等待 L2 |
| 等待首字 | 中性或保守的倾听偏置 | 否定、引用、反讽与未知语言不过度表演；无头身位移 |
| 文本/语音表达 | 与实际呈现或播放片段匹配 | 人工延迟 TTS、分段播放、取消和重试时不提前变脸 |
| 播放结束 | 按配置释放到角色基线 | 以实际播放结束为依据，避免文本结束时提前释放 |
| 故障或切换 | 无效结果丢弃，基础聊天继续 | 超时、异常、后台恢复与切换不留下旧表情状态 |

延迟数值是后续基准需要确定的预算，不能把“16ms 首帧”“50ms 音画对齐”或“固定 60FPS”写成跨设备保证。报告应分开列出计算耗时、排队/IPC、到可见帧的延迟及音频对齐误差，并说明设备、输入长度和分位数。

平滑实现只由 UPB 负责。依 03 选择一阶指数平滑，采用真实秒单位的 `alpha = 1 - exp(-dt / tau)`；这不是临界阻尼二阶弹簧，也不是三次样条，不同时保留另一种默认算法。具体时间常数作为配置和测试对象，不宣称固定时间内符合人类肌肉规律。

## 5. 实施门槛

1. **基线先行**：完成实际写入时序、资源能力和旧 cue 消费路径的验证，保留可回滚开关。
2. **基础闭环**：纯感知、ResponsePolicy、FaceState、Adapter、UPB 形成最小闭环；L2 未安装时通过全部基础场景。
3. **兼容迁移**：新增契约同步 Rust emitter、bridge 类型和所有消费者；`check:ipc` 仅覆盖命令注册，不替代事件验证。已有 cue 语义与动作行为有针对性的兼容测试。
4. **协议与音频**：新情绪标签和播放对齐各自通过门槛后启用，错误时退回已有路径或中性反应。
5. **可选增强**：L2 依照 [04](04-lightweight-local-onnx-emotion-models-and-integration-design.md) 的候选评估、资源与生命周期方案推进，不作为首期必要条件。
6. **数据与效果**：依据 [05](05-l1-algorithm-driven-core-foundation-architecture-and-moat.md) 的独立评测与规则治理逐步扩展，发布前提交可复核结果。

本轮裁决确定的是边界、风险和验收要求，没有批准未经验证的算法精度、模型性能或面部视觉效果。
